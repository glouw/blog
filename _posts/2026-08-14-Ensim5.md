Ensim5 explores compiler friendly SIMD expressions and cache locality for isentropic flow and kinematic equations.

<iframe width="720" height="405" src="https://www.youtube.com/embed/za0bQ6HqPRg" frameborder="0" allow="autoplay; encrypted-media" allowfullscreen></iframe>

One can model a piston flow lane from plenum intake to exhaust as nine chambers
(atmosphere, plenum, throttle, runner, piston, runner, exhaust, exhaust, atmosphere) with eight nozzles,
mapping perfectly to floating point AVX256 or doubling point AVX512. The latter is required for stability, but sharing
at least the nozzle velocity equation with nozzle count `N = 8`:

```
/*
 *               ______________
 *              /
 *             /  y * Pt / pt
 *            /  -------------
 *           /       y - 1  2
 * u = M _  /    1 + ----- M
 *        \/           2
 *
 *        Pt
 * pt = -------
 *      Rs * Tt
 *
 */

fn void calc_nozzle_velocities()
{
    for(size_t i = 0; i < N; i++)
    {
        const real Rs = g_specific_gas_constant_j_per_kg_k;
        const real Tt = chamber_total_temperature_k[i];
        const real M = nozzle_mach[i];
        const real X = g_gamma * Rs * Tt;
        const real Y = 0.5_r * (g_gamma - 1.0_r) * M * M;
        const real u = M * sqrt(X / (1.0_r + Y));
        const real A = chamber_nozzle_real_flow_area_m2[i];
        const real mute = A == 0.0_r ? 0.0_r : 1.0_r;
        nozzle_velocity_m_per_s[i] = u * mute;
    }
}
```

This allows for a real time engine to compute an entire piston's chamber gas flow speed from intake to exhaust with a couple cache line reads
and a ~15 instructions. An inline-8 engine can compute its flow field in less than 100 instructions.

Likewise, piston inertia torque can also be calculated with some clever sinusoid identity swaps and precomputed sin and cos thetas,
for eight pistons in parallel, with this inline-8 configuration:

```
/*
 * Hailemariam Nigus. Kinematics and Load Formulation of Engine Crank Mechanism. Mechanics, Materials/
 * Science & Engineering Journal, 2015, ⟨10.13140/RG.2.1.3257.1928⟩. ⟨hal-01305936⟩
 *
 *           2      r            1             3r
 * Ti = I * w * [ ---- sin(t) - --- sin(2t) - ---- * sin(3t) ]
 *                 4l            2             4l
 *
 * These identities free up the SIMD lanes:
 *
 *     sin(2t) = 2 sin(t) * 1 cos(t)
 *
 *                               3
 *     sin(3t) = 3 sin(t) − 4 sin (t)
 *
 */

fn void calc_inertia_torques()
{
    for(size_t i = 0; i < W; i++)
    {
        const real r = crank_throw_length_m[i];
        const real l = connecting_rod_length_m[i];
        const real I = moment_of_inertia_kg_m2[i];
        const real w = crankshaft_angular_velocity_r_per_s;
        const real rl = r / l;
        const real s = sint[i];
        const real c = cost[i];
        const real X = 0.25_r * rl * s;
        const real Y = s * c;
        const real Z = 0.75_r * rl * (3.0_r * s - 4.0_r * s * s * s);
        inertia_torque_n_m[i] = I * w * w * (X - Y - Z);
    }
}
```

#### perf stat

Powering our flow velocity model with our piston kinematic model above, we output to a branchless
and cache efficient one dimensional Lax-Friedrichs-Reimann CFD pipe for audio generation, generating
48000 audio samples in 0.2 seconds:

`Intel(R) Core(TM) i7-8665U CPU @ 1.90GHz`

While single threaded performance is _excellent_ even on a T490, pipe audio fidelity is reduced due
to incompatible one dimensional CFD boundary conditions when connected to the zero dimensional isentropic flow model.
I suspect a full 1D LFR pipe model is required to get the most realistic sounding exhaust pulse waves.
